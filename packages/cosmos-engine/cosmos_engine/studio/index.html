    01 / WHAT IT IS

    경험을
    연결 가능한 지식으로.

    Cosmos Studio는 포트폴리오의 온톨로지를 갱신하는 로컬 작업실이에요. 대화와 자료에서 사실을 찾고, 직접 검토해 승인한 내용만 지식 그래프에 연결해요.

    스크롤하여 작동 방식 살펴보기 ↓
    02 / INPUT & EXTRACTION

    형식이 달라도
    하나의 입력 흐름.

    채팅 대화, 문서, PDF, 이미지, 코드, CSV와 JSON, 공개 URL과 자막을 받을 수 있어요. 선택한 모델이 내용을 읽어 사실과 관계의 후보를 만들어요.

    스캔 PDF의 OCR과 영상 직접 전사는 지원하지 않아요. 자막이나 텍스트를 함께 넣어 주세요.

    03 / ONTOLOGY

    사실을 타입과
    관계로 설계해요.

    문장 전체를 노드 하나에 넣지 않아요. 사람, 경력, 기여, 프로젝트, 역량, 글과 출처를 서로 다른 타입으로 기록하고 ID와 요약, 근거를 붙여요.

    구조 예시
    나 hasContribution 기여 inProject 프로젝트
    기여 demonstrates 역량
    관계 규칙연결 가능한 노드 타입과 중복 관계를 검사해요.
    파생 관계확인된 두 경로가 있으면 workedOn을 생성하고 원래 경로를 남겨요.
    승인 기준모든 기록에는 출처가 필요해요. 제안 관계는 검토 전까지 확정 사실로 취급하지 않아요.
    04 / SEMANTIC LAYER

    관계에서 답을
    검증 가능하게 찾아요.

    시맨틱 레이어는 타입과 관계를 정해진 질문에 맞춰 조회해요. 유사한 문장을 찾는 것과 달리, 어떤 경로가 답의 근거인지 함께 반환해요.

    “어떤 역량을 무엇으로 입증했나요?”
    01 경로나의 hasCapability 관계와 기여 → demonstrates → 역량 경로가 일치하는지 확인해요.
    02 필터출처가 확인된 관계와 조회 날짜에 유효한 관계만 사용해요.
    03 결과역량 기록과 기여에서 역량까지의 경로, 원본 근거를 함께 표시해요.

    portfolio, career, research, writing도 각각 정해진 관계를 조회해요. 공개 범위는 정적 배포 단계에서 별도로 적용해요. 자유로운 LLM 추론을 검증된 사실로 바꾸지 않아요.

    05 / APPROVE & PUBLISH

    승인한 지식만
    Cosmos에 남아요.

    승인한 기록을 그래프, 검색 데이터와 JSON-LD로 생성해요. GitHub Pages에는 정적 결과물만 배포되고, 원본 자료와 검토 중인 후보는 로컬에 남아요.
